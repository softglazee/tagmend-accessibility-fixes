Accessibility fixes for theme, page builder and WooCommerce HTML: common WCAG failures repaired on your server. No overlay. Preview each fix.

== Description ==

Tagmend adds an Accessibility Fixes menu to the WordPress admin. This development version adds missing image alt text from the Media Library, gives images inside named links and buttons an empty alt, names empty links and buttons from reliable sources (your site name, email and phone links, known social networks, search forms, menu toggles and icon classes), names form fields without a label from their placeholder or a known field name, adds the post title to "Read more" links, hides decorative icons inside named links and buttons, resets positive tabindex values, takes hidden duplicate links out of the keyboard tab order, labels theme menus with their menu location name, hides empty headings where that leaves the heading levels in order, and repairs untitled iframes, a missing or malformed page language and viewport tags that block zooming. On WordPress 6.9 or later it also adds a skip link to pages that have none and repairs skip links whose target is missing; when another plugin switches off the WordPress page buffer these repairs need (some page builders do), those page-wide repairs and the viewport repair do not run, and the other repairs still work on post content, template parts, widgets and menus. Filling empty alt text from the Media Library, using the product name for WooCommerce product images, taking focusable items inside hidden content out of the tab order, giving repeated form fields their own ids (WordPress 6.9 or later), noting links that open a new tab and a visible focus outline are available and start Off. Each fix has its own Off, Preview and Live setting; nothing changes for visitors until a fix is set to Live. An administrator can scan pages from the Reports screen (the home page, one address, or a suggested set of pages) or with "Scan this page" in the admin bar: each scan runs in the administrator's own browser request, changes nothing on the page, and stores a report of what each fix would change and what still needs a person in the site's own database. Reports also list low text contrast where an element sets both its text colour and its background colour itself (in its style attribute or with block editor colour presets), with the ratio and the threshold it misses; other text contrast needs a check in the browser. Report details lists the changes by fix, can move a fix to Live or skip it on one page, and names what the plugin does not check; the Activity log keeps a dated record of fix changes, scans and pages served unrepaired, with CSV export. Reports are also readable with WP-CLI (wp softglaze-a11y report). The Overview shows three first steps until a fix is Live, how many fixes are Live, in Preview and Off, whether the page-wide repairs can run, the newest reports and the pages served unrepaired in the last 7 days; after a fix goes Live it names the page-cache plugin it finds and reminds you to clear its cache. Settings switch the page-wide repairs and the admin bar menu, set the size and time limits and the paths never repaired, and choose whether deleting the plugin also deletes its data (off by default). On a multisite network the plugin is activated per site. The plugin makes no HTTP requests.
